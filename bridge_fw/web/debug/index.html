VIA 隧道回路测试 网页 → 蓝牙/2.4G → 模组 → UART → SK32 → 回程（32B 裸透传，无 report ID / status 字节）
自检报文GET_PROTOCOL_VERSION 往返
发送 32B 报文：byte0=0x01（id_get_protocol_version）、byte1=0x00、byte2=0x0D（VIA_PROTOCOL_VERSION=0x000D），其余补零；期望 SK32 VIA 原样回发，byte0=0x01、byte1=0x00、byte2=0x0D。首字节 0x01 天然避开 Dongle 对首 3 字节 “OTA” 的 OTA 拦截。
设备标识｜WebHID 过滤器（通路 A / B 共用）
配置通路 A（Dongle）与通路 B（BLE 模组）调用 navigator.hid.requestDevice 时使用的 VID / PID 过滤器，可自由填写以匹配任意设备。输入为 1~4 位十六进制（可带或不带 0x 前缀）。修改后重新点击「连接 Dongle / 连接 BLE 模组」即生效。
通路 C｜LD7 键盘 VIA 数据模拟（经串口扮演 SK32/LD7） 未启用
网页直接扮演 LD7 键盘（SK32/QMK VIA）应答桌面 VIA，无需真实 SK32。桌面 VIA 经蓝牙（HOGP RID5）或 2.4G（Dongle RID0）到模组 → 模组把 VIA Raw HID 经 UART 转成 EVT_TUNNEL_BLE(0x86)/EVT_TUNNEL_USB(0x85) → 本页通过串口（WebSerial）接收并应答 CMD_TUNNEL_BLE(0x19)/CMD_TUNNEL_USB(0x18)。镜像 quantum/via.c（协议版本 0x000D）、LD7 键位（1×7 = Z X C V A LCTL ENTER、4 层）与 qmk_rgb_matrix 自定义值。模拟状态保存在浏览器 localStorage，改动可跨刷新保留。
通路 A｜WebHID → 接收器 Dongle → 2.4G 未连接
选择 2.4G 接收器（usagePage 0xFF60 的 VIA Raw HID 接口，VID/PID 取上方「设备标识」输入，默认 0x0194 / 0x0464，无 Report ID）。下行 EP3 OUT → 2.4G → 键盘模组 → UART EVT_TUNNEL_USB(0x85) → SK32 raw_hid_receive；上行原路返回。
通路 B｜WebHID → 键盘模组 BLE（HOGP RID 5） 未连接
先在系统蓝牙里配对键盘，再在此选择键盘模组（usagePage 0xFF60 的 HOGP vendor 集合，VID/PID 取上方「设备标识」输入，默认 0x0194 / 0x0464，Report ID 5）。下行写 vendor OUT → 模组 → UART EVT_TUNNEL_BLE(0x86) → SK32 raw_hid_receive；上行经 vendor IN 通知返回。
注意：两条通路 VID/PID 现已相同（均为 LD7 键盘标识），浏览器选择框会同时列出二者，靠 Report ID 区分（Dongle=RID0 / BLE=RID5）。
模组 BLE HID 服务注册取证（RID5 IN/OUT 属性 handle 等）可在「命令台」执行 HID_DIAG(0x2B)（需串口直连模组）。
批量稳定性测试（通路 A / B） 空闲
对已连接通路连续做 N 次 VIA 自检往返（报文内嵌 LE16 序号，用于识别丢包/错序/重复）。严格单发、不重试：超时即计丢包；回包序号不匹配则计错序/重复。统计成功次数、丢包率与 RTT 最小/均值/中位/P95/P99/最大、用时与速率。默认 10000 次。
